# knowledge-assistant Specification

## Purpose
The knowledge assistant is a chat in which any signed-in user asks luthiery questions and receives streamed answers generated by an LLM grounded in passages retrieved from the shared `reference-library`, with numbered sources and inline figures. Conversations are saved per user. The same server-side "ask" entry point is reused by other features, such as the wood analysis in `wood-panel-properties`.

## Requirements

### Requirement: Chat Availability
The system SHALL provide the assistant chat at `/chat` to every signed-in user, whether or not they are an admin; signed-out visitors cannot use it (see `app-shell` for sign-in and navigation).

#### Scenario: Regular user opens the chat
- **GIVEN** a signed-in user without the admin role
- **WHEN** the user opens `/chat`
- **THEN** the conversation list and the message pane are shown

### Requirement: Conversation Privacy
The system SHALL let each user list, open, continue and delete only their own conversations in the chat, including admins (oversight of other users' conversations belongs to `admin-console`). The server SHALL reject any attempt by a non-admin user to read another user's conversation or its messages, and any attempt by anyone, admins included, to add to, change or delete them.

#### Scenario: Admin's chat shows only their own conversations
- **GIVEN** an admin and another user who each have conversations
- **WHEN** the admin opens `/chat`
- **THEN** only the admin's own conversations are listed

#### Scenario: Foreign conversation
- **WHEN** a non-admin user asks to continue a conversation that belongs to someone else
- **THEN** no messages of that conversation are read or added for that user

### Requirement: Conversation Data
The system SHALL persist, for each conversation: a unique identifier, the owning user (required), a title (text, default "New Conversation"), a creation timestamp and a last-activity timestamp that is updated whenever a message is added. Deleting a conversation deletes all its messages.

#### Scenario: Last activity updates
- **GIVEN** a conversation last used yesterday
- **WHEN** the user asks a new question in it today
- **THEN** its last-activity time becomes today

### Requirement: Message Data
The system SHALL persist, for each message: a unique identifier, its conversation, its role (`user` or `assistant`), its text content (required), a creation timestamp, and metadata holding the sources used for that exchange and, for answers, the name of the model that generated it.

#### Scenario: Answer stored with sources
- **WHEN** an answer finishes streaming in a saved conversation
- **THEN** the stored answer includes its text, its sources and the model name

### Requirement: Conversation List
The system SHALL list the user's conversations sorted by last activity, most recent first, each showing its title on one truncated line and its last-activity date and time in the user's locale, with the open conversation highlighted. With no conversations it shows "No conversations yet.". When the chat opens, the most recent conversation is selected automatically.

#### Scenario: Auto-select on open
- **GIVEN** a user with three conversations
- **WHEN** the user opens the chat
- **THEN** the most recently active conversation is shown with its messages

#### Scenario: No conversations
- **WHEN** a user with no conversations opens the chat
- **THEN** "No conversations yet." is shown

### Requirement: Open a Conversation
The system SHALL show the messages of the selected conversation in chronological order: questions as plain text preserving line breaks, aligned to the user's side, and answers rendered as formatted text (see Answer Rendering).

#### Scenario: Switch conversation
- **WHEN** the user clicks another conversation in the list
- **THEN** that conversation's questions and answers are shown in order

### Requirement: Start a New Conversation
The system SHALL provide a "New" action that clears the message pane; the conversation itself is created when the first question is sent, titled with the first 100 characters of that question, and then appears at the top of the list as the selected conversation. Titles are derived automatically; users cannot rename conversations.

#### Scenario: First question creates the conversation
- **WHEN** a user clicks "New" and asks "What thickness should a spruce top be?"
- **THEN** a conversation titled "What thickness should a spruce top be?" appears at the top of the list and is selected

### Requirement: Delete a Conversation
The system SHALL let a user delete a conversation from the list after a confirmation dialog titled "Delete Conversation" saying "Are you sure you want to delete this conversation? This action cannot be undone." with Delete and Cancel. Confirming deletes the conversation and all its messages and clears the pane if it was open; a failure shows "Failed to delete conversation".

#### Scenario: Delete the open conversation
- **GIVEN** the user is viewing a conversation
- **WHEN** the user deletes it and confirms
- **THEN** it disappears from the list and the message pane is cleared

#### Scenario: Cancel deletion
- **WHEN** the user clicks the delete action and then Cancel
- **THEN** the conversation remains unchanged

### Requirement: Question Input
The system SHALL provide a multi-line question box with the placeholder "Ask a question about your reference documents…" and a Send button. Enter sends; Shift+Enter inserts a line break. The question is trimmed; Send is disabled when the box is blank, and both the box and Send are disabled while an answer is being generated.

#### Scenario: Enter to send
- **WHEN** the user types a question and presses Enter
- **THEN** the question is sent and the box is cleared

#### Scenario: Blank question
- **WHEN** the box contains only spaces
- **THEN** Send is disabled and nothing is sent

### Requirement: Streaming Answer Display
The system SHALL show the question immediately and display the answer progressively as it is generated, with the indicator "Generating answer…" until it completes. The pane scrolls to the newest content (instantly when a conversation is opened, smoothly while an answer streams). When the answer completes, the conversation is reloaded from the server.

#### Scenario: Progressive answer
- **WHEN** the user sends a question
- **THEN** the question appears at once, the answer text grows as it streams, and "Generating answer…" is shown until it ends

### Requirement: Conversation Persistence
The system SHALL store each question asked in the chat, and its answer once generation has completed with non-empty text, in the current conversation together with the sources used, so that reopening the conversation later shows the same exchange.

#### Scenario: Reopen later
- **GIVEN** a user asked two questions yesterday
- **WHEN** the user reopens that conversation today
- **THEN** both questions and both answers are shown

### Requirement: Follow-Up Questions Use History
The system SHALL give the model all earlier messages of the conversation, in chronological order, before the new question, so that follow-up questions can refer to earlier answers.

#### Scenario: Follow-up
- **GIVEN** a conversation where the user asked about X-bracing
- **WHEN** the user asks "And for a classical guitar?"
- **THEN** the answer takes the earlier exchange about X-bracing into account

### Requirement: Passage Retrieval
The system SHALL embed each question with the same model used to index the `reference-library`, compare it by cosine similarity with all indexed passages of all reference documents, keep passages whose similarity is strictly greater than an operator-configured threshold (default 0.5, to be re-tuned whenever the embedding model changes), and use at most the 10 most similar, ordered by decreasing similarity.

#### Scenario: Top passages selected
- **GIVEN** the threshold is 0.5 and 25 passages score above it for a question
- **WHEN** the question is asked
- **THEN** only the 10 highest-scoring passages are used, best first

#### Scenario: Weak matches excluded
- **WHEN** the threshold is 0.5 and the best passage for a question scores 0.48
- **THEN** no passage is used

### Requirement: No Relevant Passages
The system SHALL refuse to answer when no passage passes the similarity threshold: no answer is generated, nothing is stored, no new conversation is created, and the user sees a message stating that no relevant information was found in the reference documents and suggesting rephrasing the question.

#### Scenario: Off-topic question
- **WHEN** a user starts a new conversation by asking about an unrelated topic
- **THEN** the user sees the no-relevant-information message
- **AND** no conversation is added to the list

### Requirement: Context Formatting for the Model
The system SHALL pass retrieved passages to the model as a numbered list, each entry formatted as "[n] <passage text>" with n from 1 in similarity order and entries separated by a blank line, embedded in the answering instructions. The instructions come first (acknowledged by the model), then the conversation history, then the new question.

#### Scenario: Numbering matches sources
- **WHEN** three passages are retrieved
- **THEN** the model sees them as [1], [2] and [3]
- **AND** the sources list shows the same numbers for the same passages

### Requirement: Answer Grounding Rules
The system SHALL instruct the model to act as an assistant for technical and scientific content, to base answers on the retrieved passages and cite them by their bracket numbers (for example [1], [2]), and, when the passages do not fully answer the question, to supplement with general knowledge while giving priority to the passages.

#### Scenario: Cited answer
- **WHEN** an answer uses information from passage 2
- **THEN** the answer contains the citation marker [2]

### Requirement: Answer Language
The system SHALL write every answer in the user's selected interface language (English or French), whatever the language of the question and of the retrieved reference passages. Technical terms, symbols, formulas and figure IDs are kept as they are; source titles and excerpts are shown as stored.

#### Scenario: French user, English references
- **GIVEN** the user's interface language is French and the reference library is written in English
- **WHEN** the user asks "Quelle épaisseur pour une table en épicéa ?"
- **THEN** the answer is written in French and cites the English sources

#### Scenario: Language follows the interface, not the question
- **GIVEN** the user's interface language is French
- **WHEN** the user types a question in English
- **THEN** the answer is written in French

#### Scenario: English user
- **GIVEN** the user's interface language is English
- **WHEN** the user asks a question
- **THEN** the answer is written in English

### Requirement: Math and Figure Rules in Answers
The system SHALL instruct the model to reproduce LaTeX formulas from the passages exactly with their `$` (inline) or `$$` (display) delimiters, to write any new formula in LaTeX with those delimiters, to mention figures by ID as "Figure X.Y-Z" or "Fig. X.Y-Z", and never to say it cannot display images (figures are displayed automatically).

#### Scenario: Formula preserved
- **GIVEN** a retrieved passage containing `$E_L = 0.9465 \rho f^2 L^4 / t^2$`
- **WHEN** the answer uses that formula
- **THEN** the answer shows it typeset, not converted to plain words

### Requirement: Generation Settings
The system SHALL choose the generation model on the server (clients cannot choose it) and generate with temperature 0.7, nucleus sampling top-p 0.95, top-k 40 and at most 8192 output tokens. The model is a current Google Gemini Flash model whose identifier the operator configures; the legacy model, Gemini 2.0 Flash (experimental), was shut down by Google in 2026.

#### Scenario: Client cannot pick the model
- **WHEN** a client requests a specific model name
- **THEN** the server-configured model is used anyway and reported in the response metadata

### Requirement: Answer Rendering
The system SHALL render answers with the same Markdown, LaTeX math and safe-rendering rules as the `reference-library` viewer, so formulas are typeset and no HTML or script in an answer is executed.

#### Scenario: Script in an answer
- **WHEN** an answer contains `<script>` text
- **THEN** it is not executed

### Requirement: Sources Display
The system SHALL show under each completed answer a collapsible "Sources (N)" section, collapsed by default, listing every passage used as context in its numbered order as "[n] <document title>" (or "Source" when untitled) with a two-line excerpt of the passage. Sources belong to their own answer: they are shown again when the conversation is reopened and never under another answer or conversation.

#### Scenario: Expand sources
- **WHEN** an answer that used 4 passages completes and the user clicks "Sources (4)"
- **THEN** four entries [1] to [4] with document titles and excerpts are shown

#### Scenario: Switching conversations
- **GIVEN** the user just got an answer with sources in conversation A
- **WHEN** the user opens conversation B
- **THEN** none of conversation A's sources are shown in B

### Requirement: Source Links
The system SHALL let a user who can access the reference library (an admin) click a source to open the cited document in the reference viewer (`/references?docId=<id>`). For users without that access, sources SHALL still show title and excerpt but SHALL NOT link to a page they cannot open.

#### Scenario: Admin follows a source
- **WHEN** an admin clicks source [2]
- **THEN** the reference viewer opens on the document of passage 2

#### Scenario: Non-admin sees sources
- **WHEN** a non-admin user expands the sources of an answer
- **THEN** titles and excerpts are shown without links to the reference library

### Requirement: Inline Figures in Answers
The system SHALL display, right after each answer paragraph that mentions a figure as "Fig X.Y-Z", "Fig. X.Y-Z", "Figure X.Y-Z" or "Figure. X.Y-Z" (case-insensitive), the image attached to that answer's sources with the same figure ID, once per paragraph, captioned with its caption or figure ID; clicking it opens the full-size image in a new tab. Mentions without a matching image show no image.

#### Scenario: Figure mentioned in the answer
- **GIVEN** a source passage carries figure "4.4-2"
- **WHEN** an answer paragraph says "As shown in Fig. 4.4-2, ..."
- **THEN** that figure's image and caption appear directly below the paragraph

### Requirement: Chat Error Display
The system SHALL show any failure while asking as "Error:" followed by the message, keep the question visible, remove the empty answer placeholder, and re-enable the input. Failures that occur after the answer started streaming SHALL also be shown, not silently ignored.

#### Scenario: Generation service failure
- **WHEN** the generation service fails while the answer is streaming
- **THEN** the user sees "Error:" with a message and can ask again

### Requirement: Shared Ask Entry Point
The system SHALL expose one server entry point used by the chat and by other features (such as the wood analysis in `wood-panel-properties`) that accepts a question (required, non-empty after trimming), an optional conversation to continue, a persist flag (default on) and the answer language (English or French, see Answer Language), and requires a signed-in user; requests without valid authentication SHALL be rejected as unauthorized.

#### Scenario: Wood analysis reuses the entry point
- **WHEN** the wood analysis sends its generated question with persist off
- **THEN** it receives a streamed, source-grounded answer using the same retrieval and generation rules as the chat

#### Scenario: Unauthenticated call
- **WHEN** the entry point is called without a valid session
- **THEN** it responds with an unauthorized error and calls no external service

### Requirement: Non-Persistent Asks
The system SHALL, when persist is off and no conversation is given, answer without creating a conversation or storing any message, without history, and without returning a conversation identifier; retrieval and the no-relevant-passages refusal apply unchanged.

#### Scenario: One-off analysis leaves no trace
- **WHEN** a feature asks a question with persist off
- **THEN** no conversation appears in the user's chat list

### Requirement: Ask Response Stream
The system SHALL deliver the answer as an ordered event stream: first metadata (conversation identifier if any, the sources with number, document identifier, title, excerpt, similarity and attached images with URL, caption and figure ID, and the model name), then text fragments in order, then a completion event; a failure after streaming starts SHALL produce an error event with a message.

#### Scenario: Normal stream
- **WHEN** a question is answered
- **THEN** the client receives metadata, then one or more text fragments, then completion

### Requirement: Ask Error Responses
The system SHALL answer failures that happen before streaming with a non-streamed error carrying a human-readable message: a client error for an empty question or when no relevant passages are found, an unauthorized error for missing or invalid authentication, and a server error for embedding or generation service failures.

#### Scenario: Empty question
- **WHEN** the entry point receives a blank question
- **THEN** it returns an error stating that a question is required

### Requirement: Assistant Operator Configuration
The system SHALL read the Google AI credential (one key serves embeddings and generation) and the generation model identifier from operator-supplied server-side configuration and never expose them to the browser; if it is missing, every ask SHALL fail with an error saying the key is not set.

#### Scenario: Missing key
- **GIVEN** the operator has not configured the AI service key
- **WHEN** a user asks a question
- **THEN** the user sees an error that the key is not set

### Requirement: Assistant Localization
The system SHALL present all chat text (labels, placeholders, confirmations, indicators and user-facing error messages, including the no-relevant-information message) in English and French according to the user's selected language.

#### Scenario: French interface
- **GIVEN** the interface language is French
- **WHEN** the user opens the chat
- **THEN** the new-conversation button reads "Nouveau" and the placeholder reads "Posez une question sur vos documents de référence…"
